Runtime delta versus no_break

Every bar is one row from the new rerun. The zero line is no_break. Positive bars are slower than the intact-huge-page baseline, and negative bars are faster. This is the quickest way to see whether the penalty comes from splitting everything, splitting one key, or both. The plotted value is percent difference from no_break, not raw seconds.

Hotness versus runtime impact

The 10 split-only rows only. The x-axis is the access count from the captured trace, and the y-axis is the runtime delta versus no_break in percent. Bubble size reflects dTLB misses so you can see whether the slowest keys are also the keys with the biggest TLB pressure.

dTLB counters by row

Mean dTLB loads and misses for each row in this rerun. These are the new metrics added to replay output. They help answer whether a slower row is also carrying more translation overhead.
